Routed Attention: Learning When to Think Hard

A router learns when to use expensive O(N²) attention vs cheap O(N) convolution. The result: 75-99% compute savings while matching full attention accuracy.

---

The Problem

My previous work ("Attention May Not Be What You Need") showed that O(N) learned convolution beats O(N²) softmax attention on language modeling perplexity. The result was clean: simpler is better.

But there was a caveat. Convolution is a local operation. It can only see tokens within its kernel size. For language modeling, where most predictions depend on recent context, this works fine. But for precise retrieval - "what was the 5th word in the sentence?" - convolution fails completely.

I tested this with an associative recall task. The model sees a sequence of key-value pairs, then a query key, and must output the corresponding value. Like a dictionary lookup stretched across a sequence.

Results were stark:

| Distance | Standard O(N²) | Conv K=64 |
|----------|----------------|-----------|
| 30       | 100%           | 99.8%     |
| 62       | 100%           | 80%       |
| 126      | 99%            | ~1%       |

Conv fails beyond kernel size. It's a local feature extractor, not recurrent memory.

This created a dilemma. O(N) convolution wins on throughput and even perplexity - but it can't do retrieval. O(N²) attention can do retrieval - but it's slow and scales poorly.

What if we could have both?

---

The Idea: Route Per Position

The key insight: not every position needs the same computation.

Most tokens in a sequence can be predicted from local context. The word after "the" is probably a noun. The word after "running" is probably an adverb or period. You don't need to search the entire sequence to make these predictions.

But some positions genuinely need long-range information. When you see a pronoun, you need to find its antecedent. When you see a closing bracket, you need to match it with the opening one. These positions benefit from attention.

What if each position could choose?

I built a router: a small network that looks at each position and decides whether to use conv (cheap, local) or attention (expensive, global). The router is learned end-to-end with the rest of the model.

The architecture:

```python
class RoutedAttentionLayer(nn.Module):
    def __init__(self, dim, num_heads, kernel_size=64):
        # Two pathways
        self.conv_layer = LearnedConvAttention(dim, num_heads, kernel_size)
        self.attn_layer = StandardAttention(dim, num_heads)

        # Router: per-position decision
        self.router = nn.Sequential(
            nn.Linear(dim, dim // 4),
            nn.GELU(),
            nn.Linear(dim // 4, 2)  # [conv_score, attn_score]
        )

    def forward(self, x, temperature=1.0):
        # Get routing decision for each position
        route_logits = self.router(x)  # [batch, seq, 2]

        # Gumbel-softmax for differentiable discrete choice
        route_weights = F.gumbel_softmax(route_logits, tau=temperature, hard=True)

        # Run both pathways
        conv_out = self.conv_layer(x)
        attn_out = self.attn_layer(x)

        # Combine based on routing
        return (route_weights[..., 0:1] * conv_out +
                route_weights[..., 1:2] * attn_out)
```

The Gumbel-softmax trick is crucial. During training, we need gradients to flow through the discrete routing decision. Gumbel-softmax adds noise to make the choice soft during the backward pass, but hard (0 or 1) during the forward pass. The router learns which positions benefit from attention.

---

First Attempt: Complete Failure

I trained this on the associative recall task. Every model achieved ~1% accuracy. Random chance.

Something was deeply wrong.

After debugging, I found three separate bugs:

Bug 1: The optimizer was being created inside the training loop.

```python
def train_epoch(model, config, ...):
    optimizer = torch.optim.AdamW(model.parameters())  # BUG!
    for batch in data:
        ...
```

Every epoch started with a fresh optimizer. Momentum, adaptive learning rates - all reset. The model couldn't accumulate learning across epochs.

Fix: Create the optimizer once, outside the loop.

Bug 2: Training on impossible data.

The original setup trained on a mix: 30% pure retrieval sequences, 70% "language-like" random sequences. But the language-like sequences were just random tokens - impossible to predict. The model was being trained on mostly noise.

Fix: Train on pure retrieval only. That's the task we're testing.

Bug 3: Loss averaged over all positions.

```python
loss = F.cross_entropy(logits.view(-1, vocab_size), targets.view(-1))
```

This averages loss over every position in the sequence. But only the last position (after the query) tests retrieval. The retrieval signal was diluted by loss from 500 irrelevant positions.

Fix: Compute loss only on the retrieval position.

```python
loss = F.cross_entropy(logits[:, -1], targets)
```

After these fixes, attention-only solved the task perfectly. But routed attention still failed.

---

The Router's Dilemma

The problem was subtle. I had added a cost penalty to encourage using conv over attention:

```python
loss = task_loss + lambda * attention_usage
```

The idea: make attention expensive so the router only uses it when necessary.

But the router was initialized randomly. At the start of training, it had no idea which positions needed attention. The cost penalty immediately pushed it toward conv for everything. Conv can't solve long-range retrieval. The model never learned the task.

It's a chicken-and-egg problem. The router needs to know which positions benefit from attention. But it can only learn that by using attention on those positions. The cost penalty prevents exploration.

---

The Solution: Curriculum Learning

The fix was curriculum learning. Train in two phases:

Phase 1: Set λ=0. No attention penalty. Let the model learn to solve the task using whatever routing it discovers naturally. The router learns when attention is genuinely necessary.

Phase 2: Gradually increase λ. Now that the router knows which positions need attention, it can maintain accuracy while minimizing attention usage on positions that don't need it.

```python
def train_curriculum(model, seq_len, device):
    # Phase 1: Learn the task (no cost penalty)
    phase1_config = Config(attention_cost=0.0)
    for epoch in range(phase1_epochs):
        train_epoch(model, optimizer, phase1_config, seq_len)
        acc, attn_usage = evaluate(model, phase1_config, seq_len)
        if acc >= 0.99:
            break  # Task learned

    # Phase 2: Minimize attention while maintaining accuracy
    target_lambda = 0.5
    for epoch in range(phase2_epochs):
        current_lambda = target_lambda * (epoch / phase2_epochs)
        phase2_config = Config(attention_cost=current_lambda)
        train_epoch(model, optimizer, phase2_config, seq_len)
```

The gradual λ increase is important. Jumping straight to λ=0.5 after phase 1 causes the router to collapse immediately to all-conv, losing accuracy. Ramping up slowly lets the router find the minimum attention needed to maintain performance.

---

Results

I tested four configurations on associative recall:

1. Attention Only: Standard O(N²) attention, baseline
2. Conv Only: O(N) learned convolution, no attention
3. Routed λ=0.1: Low attention penalty
4. Routed λ=0.5: High attention penalty

Tested on sequence lengths from 128 to 2048 tokens:

| Distance | Attn Only | Conv Only | Routed λ=0.1 | Routed λ=0.5 |
|----------|-----------|-----------|--------------|--------------|
| 126      | 100%      | 1%        | 100% (16%)   | 100% (0.3%)  |
| 254      | 100%      | 2%        | 100% (25%)   | 99% (0.2%)   |
| 510      | 100%      | 2%        | 100% (25%)   | 100% (25%)   |
| 1022     | 99%       | 2%        | 36% (74%)    | 98% (90%)    |
| 2046     | 82%       | 2%        | 2% (35%)     | 97% (38%)    |

The percentages in parentheses show attention usage - what fraction of positions used the expensive attention pathway.

At short distances (126-254), routed attention achieves:
- 100% accuracy
- Near-zero attention usage (0.2-0.3%)
- ~99% compute savings

At medium distances (510), routed attention achieves:
- 100% accuracy
- 25% attention usage
- 75% compute savings

At long distances (1024+), phase 1 doesn't converge within 25 epochs. The model needs more training time or capacity to learn such long-range dependencies. But λ=0.5 still reaches 97-98% accuracy, close to the 82-99% of full attention.

---

What the Router Learns

The routing patterns are interpretable. In a sequence like:

[K1:V1] [K2:V2] [K3:V3] ... [Q=K2] [?]

The router learns to use conv for most key-value pairs (local processing suffices) but attention for the query position (needs to search the entire sequence for the matching key).

This is close to optimal. You only need O(N²) computation for positions that genuinely require global search. Everything else can use O(N).

The 25% attention floor at longer distances is interesting. Even with aggressive λ=0.5 penalty, the router maintains 25% attention usage. This suggests a quarter of positions genuinely benefit from long-range context, even when conv could handle the local pattern matching.

---

The λ Tradeoff

Higher λ means more aggressive attention minimization:

- λ=0.1: Conservative. Gets 100% accuracy but uses 16-25% attention.
- λ=0.5: Aggressive. Pushes attention to near-zero where possible, sometimes at slight accuracy cost (99% vs 100%).

For distance 126, λ=0.5 achieves 100% accuracy with only 0.3% attention. That's roughly 1 position per sequence using the expensive pathway. Near-optimal efficiency.

For distance 510, both λ values converge to 25% attention. The task requires this much global context - the router can't push below it without losing accuracy.

For distance 1024+, λ=0.5 actually helps. The higher pressure forces the router to be more selective, which seems to regularize training. The λ=0.1 model struggles to converge because it's exploring too many routing configurations.

---

Compute Implications

The practical speedup depends on attention usage.

Full attention is O(N²). Conv is O(N). If the router uses attention on fraction p of positions, the effective complexity is:

O(N + p*N²)

For p=0.003 (0.3% attention at distance 126), this is essentially O(N).
For p=0.25 (25% attention at distance 510), this is O(N + 0.25*N²).

At N=512, 25% attention means ~65,000 attention operations instead of ~260,000. A 4x reduction.

At N=2048, even 38% attention means ~1.6M operations instead of ~4.2M. A 2.6x reduction.

The savings grow with sequence length because the O(N²) term dominates at large N.

---

Adaptive Batch Sizing

One practical issue: longer sequences require more memory.

At 2048 tokens with batch size 32, I hit CUDA out-of-memory errors. The attention computation alone needs O(N²) memory.

I implemented adaptive batch sizing:

```python
def get_batch_size(seq_len):
    if seq_len <= 256:
        return 32
    elif seq_len <= 512:
        return 24
    elif seq_len <= 1024:
        return 16
    elif seq_len <= 2048:
        return 8
    else:
        return 4
```

Smaller batches for longer sequences. The total gradient signal stays similar (more steps compensate for smaller batches), but memory stays bounded.

---

Inference with KV Cache

A practical question: how does routed attention work with KV caching during autoregressive generation?

The challenge: if position i routes to conv (no attention), it has no K/V cached. But position j might route to attention and need to attend to position i.

The solution: always cache K/V, route only the aggregation.

Every position computes and caches K, V (cheap O(1) projections). Only the expensive O(N) attention aggregation is routed:

- Attention-routed positions: full Q·K^T aggregation over cache
- Conv-routed positions: skip aggregation, use O(1) convolution

Measured on GPU:

| Operation | Latency | Scaling |
|-----------|---------|---------|
| Attention | ~335 μs | O(N) |
| Conv (k=64) | ~148 μs | O(1) |
| Speedup | 2.3x | - |

Effective inference speedup:

- At 99.7% conv (distance 126): ~2.2x speedup
- At 75% conv (distance 510): ~1.45x speedup
- At 10% conv (distance 1024): ~1.06x speedup

Memory is unchanged - must keep full KV cache since any future position might use attention. The savings are purely computational.

---

What This Means

Routed attention proves that O(N²) computation isn't necessary everywhere - just where it matters.

Most positions can be predicted locally. Only a few need global context. A learned router can distinguish them.

This suggests a new architecture paradigm: instead of choosing between attention (accurate but slow) and linear alternatives (fast but limited), use both. Let the model decide per-position.

The curriculum learning insight is broadly applicable. When you have competing objectives (accuracy vs efficiency), don't optimize both from the start. First learn to solve the task, then optimize for efficiency while maintaining the solution.

---

Limitations

Training difficulty at long range. At 1024+ tokens, phase 1 needs more than 25 epochs to learn the retrieval task. The model eventually converges but slowly. Longer sequences may need architectural changes, not just more training.

Fixed kernel size. The conv pathway uses kernel size 64. For very long sequences, a larger kernel might help the conv pathway handle more positions, reducing the load on attention.

Single-layer routing. The router decides at each position independently. A multi-layer approach might learn hierarchical routing - use conv in early layers for local features, attention in later layers only where needed.

Task-specific testing. Associative recall is a clear test case but artificial. Real language might have different routing patterns. The 25% floor at longer distances might be lower or higher for natural text.

---

Connection to Mixture of Experts

Routed attention resembles Mixture of Experts (MoE), but with a key difference.

In MoE, each token is routed to one of several expert networks, all with similar computational cost. The goal is capacity (more parameters) without proportional compute (sparse activation).

In routed attention, the experts have different computational costs. Conv is O(N), attention is O(N²). The goal is efficiency (less compute) without losing capability (attention when needed).

MoE uses top-k routing with load balancing to ensure all experts are used. Routed attention uses binary routing with a cost penalty to minimize expensive expert usage.

Both share the insight that not all inputs need the same processing.

---

Future Directions

Multi-resolution routing. Instead of binary conv/attention, offer multiple options: small kernel conv (very local), large kernel conv (medium range), sparse attention (selective global), full attention (complete global). The router learns the cheapest option sufficient for each position.

Content-dependent kernel. The conv pathway uses fixed kernel weights. What if the kernel itself was content-dependent? A lightweight network could generate per-position kernels based on local context. This might extend conv's effective range.

Cascaded routing. Route not per-position but per-layer and per-position. Early layers might use all-conv, later layers selective attention. This matches the intuition that early layers extract local features, later layers integrate globally.

Pre-training with curriculum. The curriculum (task first, efficiency second) might work for pre-training language models. Train normally first, then add attention cost penalty and fine-tune. The model learns which positions actually need attention for language modeling.

Summary

I started with a limitation: O(N) convolution can't do long-range retrieval. The solution was routed attention, where each position chooses between cheap conv and expensive attention.

The journey had unexpected lessons:

1. Naive training fails. Random initialization plus cost penalty kills exploration.

2. Curriculum learning works. Learn the task first (λ=0), then optimize efficiency (increase λ).

3. Most positions don't need attention. At short distances, 0.3% suffices. Even at long distances, 25-38% is enough.

4. The router learns interpretable patterns. Query positions use attention, key-value positions use conv.

The result: 75-99% compute savings while matching full attention accuracy.

You don't have to choose between accurate and fast. You can route to both.
