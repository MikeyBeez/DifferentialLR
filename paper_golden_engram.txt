ABSTRACT

Attention mechanisms are traditionally interpreted as similarity search, where dot products between queries and keys find relevant information. We challenge this narrative. Functionally, the dot product is merely a scalar generator used to weight a sum. We demonstrate that these learned scalars are largely unnecessary by replacing them with fixed constants derived from the Golden Ratio.

We present two formulations. The Windowed Golden Engram uses fixed weights for immediate neighbors, achieving 1.3 PPL with O(N) complexity. The Damped Golden Spiral extends this to infinite context via recursive geometric decay, achieving 1.4 PPL with O(1) memory state. Critically, the spiral requires no positional encoding—the geometric decay itself encodes position.

The Damped Spiral is structurally identical to a State Space Model where the transition matrix is fixed to phi^{-1}. We have replaced Mamba's learned selective gating with a single universal constant: the Golden Ratio.

The windowed formula examines only immediate neighbors. We extend this to infinite context via recursive geometric decay:

Forward:  h_fwd[i] = T[i] + phi^{-1} * h_fwd[i-1]
Backward: h_bwd[i] = T[i] + phi^{-1} * h_bwd[i+1]
Output:   r[i] = h_fwd[i] + h_bwd[i] - T[i]

This is a bidirectional leaky integrator with a Golden Leak. Each token accumulates all past (and future) context, with exponentially decaying weights.

8. LIMITATIONS

The Golden Engram performs position-dependent routing with fixed weights. It captures context through geometric decay and directional asymmetry.

It cannot perform content-dependent routing. If the optimal attention pattern depends on what tokens appear rather than where they appear, Golden Engram will underperform. We expect this on tasks like copying specific tokens from arbitrary positions, sorting based on content, and question answering requiring retrieval of specific facts.

The 0.2 PPL gap between Golden Engram (1.4) and standard attention (1.2) represents the value of content-dependent routing on WikiText-2. For tasks dominated by positional patterns, this gap shrinks. For retrieval tasks, it grows.

APPENDIX A: WINDOWED IMPLEMENTATION

import torch
import torch.nn as nn
import math

PHI = (1 + math.sqrt(5)) / 2

class WindowedGoldenEngram(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.phi = PHI
        self.phi_inv = 1 / PHI
        self.num_heads = num_heads
        self.head_dim = embed_dim // num_heads

        self.t_proj = nn.Linear(embed_dim, embed_dim)
        self.out_proj = nn.Linear(embed_dim, embed_dim)

    def forward(self, x):
        batch, seq, dim = x.shape
        t = self.t_proj(x).view(batch, seq, self.num_heads, self.head_dim)

        t_prev = torch.roll(t, shifts=1, dims=1)
        t_prev[:, 0, :, :] = 0

        t_next = torch.roll(t, shifts=-1, dims=1)
        t_next[:, -1, :, :] = 0

        r = t + (self.phi * t_prev) + (self.phi_inv * t_next)

        output = r.reshape(batch, seq, dim)
        return self.out_proj(output)


APPENDIX B: DAMPED SPIRAL IMPLEMENTATION

class DampedGoldenSpiral(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.num_heads = num_heads
        self.head_dim = embed_dim // num_heads

        self.t_proj = nn.Linear(embed_dim, embed_dim)
        self.out_proj = nn.Linear(embed_dim, embed_dim)

        # Multi-resolution decay: phi^{-1}, phi^{-2}, phi^{-3}, phi^{-4}
        decay_rates = torch.tensor([(1/PHI) ** (i+1) for i in range(num_heads)])
        self.register_buffer('decay_rates', decay_rates)

    def forward(self, x):
        batch, seq, dim = x.shape
        t = self.t_proj(x).view(batch, seq, self.num_heads, self.head_dim)

        # Forward pass: leaky integrator from past
        fwd_outputs = []
        h_fwd = torch.zeros(batch, self.num_heads, self.head_dim, device=x.device)
        for i in range(seq):
            decay = self.decay_rates.view(1, self.num_heads, 1)
            h_fwd = t[:, i] + decay * h_fwd
            fwd_outputs.append(h_fwd.clone())
        fwd = torch.stack(fwd_outputs, dim=1)

        # Backward pass: leaky integrator from future
        bwd_outputs = []
        h_bwd = torch.zeros(batch, self.num_heads, self.head_dim, device=x.device)
        for i in range(seq - 1, -1, -1):
            decay = self.decay_rates.view(1, self.num_heads, 1)
            h_bwd = t[:, i] + decay * h_bwd
            bwd_outputs.append(h_bwd.clone())
        bwd_outputs.reverse()
        bwd = torch.stack(bwd_outputs, dim=1)

        # Combine (subtract T to avoid double-counting)
        r = fwd + bwd - t
        return self.out_proj(r.reshape(batch, seq, dim))

Memory: O(1) - only stores one vector per direction.
Compute: O(N) - one addition per token.
No positional encoding required.
